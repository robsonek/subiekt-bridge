# Audyt kodu pod kątem błędów i zgodności z Subiektem GT — 2026-06-10

Przegląd całego `RealSferaSession.cs`, kontrolerów, modeli, idempotencji, auth
i `Program.cs`. Podejrzenia weryfikowane w lokalnej dokumentacji Sfery
(`InsERT/pomoc/gta/htm/`, CHM InsERTu).

Statusy: ✅ naprawione w tym audycie · 📌 celowe (by design) · ⬜ otwarte.

## Poważne

### 1. 📌 `FormaDokumentu = 1` = faktura KSeF — CELOWE

`RealSferaSession.cs`, `CreateInvoiceCore`: dla kontrahenta-firmy ustawiane jest
`fs.FormaDokumentu = 1`. Wg `FormaDokumentuEnum.htm`: 0 = tradycyjna,
**1 = gtaFormaDokumentuFakturaKSeF**, 2 = tryb awaryjny KSeF, 3 = offline24.

**Decyzja (Robson, 2026-06-10): tak ma być.** W Polsce wszystkie faktury B2B
muszą być wystawiane jako KSeF. Bridge tylko oznacza formę dokumentu — samą
wysyłkę do KSeF wykonuje operator w Subiekcie po sprawdzeniu poprawności faktur.
Komentarz w kodzie (wcześniej mylące „FV firmowa") poprawiony. NIE zmieniać na 0.

### 2. ✅ `WartoscPodatku` nie istnieje w Sferze — `totals.vat` zawsze null

`ReadDocumentTotalsOrThrow` czytał VAT z atrybutu `WartoscPodatku`. Weryfikacja:
`grep -rl WartoscPodatku InsERT/pomoc/gta/htm/` → 0 trafień w całej dokumentacji.
Poprawny atrybut to `WartoscVat` (`SuDokument_WartoscVat.htm`, read-only, od 1.05;
kod używał go już poprawnie w `MapDokumentToQueryItem`). `TryReadDecimal` połykał
błąd, więc POST `/invoices` i `/corrections` zwracały `totals.vat = null`.

**Fix:** `WartoscPodatku` → `WartoscVat` w `ReadDocumentTotalsOrThrow`.

### 3. ✅ Anty-duplikat niezgodny z kontraktem (FS bez ref w Uwagach, PZ bez ochrony)

`FindExistingInvoiceByReference` szuka `dok_Uwagi LIKE '%ref%'`, a kontrakt
(`INTEGRATION-CONTRACT.md` §5) obiecuje tę warstwę bezwarunkowo. Tymczasem:

- **FS**: `fs.Uwagi = request.Notes` — `external_reference` NIE było doklejane
  (robiło to tylko MM). Jeśli klient nie wkleił referencji do `notes`,
  anty-duplikat FS był martwy.
- **PZ**: `CreateReceiptCore` w ogóle nie wołał anty-duplikatu, a
  `ReceiptsController` nie łapał `DuplicateInvoiceException`. Retry z innym
  Idempotency-Key = podwójny PZ = zawyżony stan magazynu.
- **KFS**: ref był w Uwagach, ale bez pre-checku przed `DodajKFS`.

**Fix:** helper `BuildUwagiWithReference` (dokleja `| ref: <external_reference>`
do Uwag, jeśli jeszcze go tam nie ma) użyty w FS, PZ i MM; anty-duplikat
(`FindExistingInvoiceByReference`) dodany do PZ (prefix "PZ") i KFS (prefix "KFS");
`ReceiptsController` zwraca 409 `DUPLICATE_RECEIPT` z `existing_*` w details.

## Średnie (naprawione 2026-06-10, druga tura)

### 4. ✅ `issue_date`, `sale_date`, `currency`, `shipping.vat_rate` przyjmowane i ignorowane

Bridge nigdy nie ustawiał `DataWystawienia` — dokument zawsze dostawał datę bieżącą
(na przełomie miesiąca = zły okres VAT). `currency: "EUR"` po cichu wystawiało
dokument w PLN. `vat_rate` pozycji usługowych — ignorowane (usługa jednorazowa
dostaje stawkę domyślną; zmiana wymaga `SuPozycja.VatId` z `sl_StawkaVAT`).
Weryfikacja w docs: `DataWystawienia` zapisywalne (przykład ustawia ją na nowym
dokumencie); data sprzedaży FS to **`DataZakonczeniaDostawy`** (`DataSprzedazy`
dotyczy TYLKO ZW i PA!); `VatProcent` read-only, ustawia się przez `VatId`.

**Fix (zasada: domyślny przypadek bez zmian, odstępstwa głośno):**
- `SetDocumentDateIfBackdated` — ustawia datę TYLKO gdy podana ≠ dzisiejsza
  (twardy `SetCom`, odmowa Sfery = widoczny błąd). FS: `DataWystawienia` +
  `DataZakonczeniaDostawy` (sale_date); KFS: `DataWystawienia`; PZ: para
  `DataMagazynowa` + `DataWystawienia` (wymóg dla dok. magazynowych).
- `currency` ≠ PLN → 422 `UNSUPPORTED_CURRENCY` (zamiast cichego PLN).
- `vat_rate` ≠ 23 na wysyłce / pozycji usługowej (EAN=null) → 422
  `UNSUPPORTED_VAT_RATE` (zamiast cichej stawki domyślnej). Pozycje towarowe
  biorą VAT z kartoteki — tam vat_rate słusznie nie ma znaczenia.
- Format dat walidowany w kontrolerach → 422 `INVALID_DATE`.

### 5. ✅ Cert path liczony od CWD zamiast od katalogu instalacji

`EnsureSelfSignedCertificate` używał `Directory.GetCurrentDirectory()`; Windows
Service ma CWD = `C:\Windows\System32`, a Kestrel rozwiązuje relative cert path
względem **ContentRoot**. Świeża instalacja wystartowana od razu jako serwis
zapisałaby cert tam, gdzie Kestrel go nie szuka. **Fix:** generator dostaje
`builder.Environment.ContentRootPath` — zawsze ta sama baza co Kestrel
(działa też dla `dotnet run`, gdzie ContentRoot = katalog projektu, nie CWD).

### 6. ✅ SQL LIKE bez escapowania `%`, `_`, `[`

`_` w LIKE dopasowuje dowolny znak — referencja `system_order_123` dopasowałaby
też `systemXorderX123` → fałszywy 409. **Fix:** `EscapeLikePattern`
(`[`→`[[]`, `%`→`[%]`, `_`→`[_]`, `'`→`''`) w `FindExistingInvoiceByReference`
i filtrze `notes_contains`. Filtr `nip` używa `=` — zostało `EscapeSqlLiteral`.

### 7. 🔶 Link PZ→FS prawdopodobnie nigdy nie powstaje — teraz przynajmniej widać

`CreateReceiptCore` ustawiał `DoDokumentuId` przez połykające `TrySet`, a przy KFS
ten atrybut okazał się read-only (`TargetParameterCountException`). Strona docs
`SuDokument_DoDokumentuId.htm` NIE oznacza go „tylko do odczytu" (w przeciwieństwie
do np. `VatProcent`), więc bez Windowsa nie da się rozstrzygnąć. **Fix częściowy:**
`SetCom` w try/catch z głośnym `LogWarning` — PZ wystawia się dalej, ale produkcja
pokaże, czy link powstaje. Do domknięcia: sprawdzić log/bazę po pierwszym PZ
z `source_invoice_subiekt_id`.

### 8. ✅ Wyciek magazynu sesji przy nieczytelnym `MagazynId`

Gdy odczyt poprzedniego `Session.MagazynId` rzucił, `previous=0` i restore był
po cichu pomijany — przestawiony magazyn zostawał dla kolejnych dokumentów bez
`warehouse_subiekt_id`. **Fix:** odczyt poprzedniego magazynu PRZED przestawieniem
jest twardy (rzuca, dokument się nie wystawia — spójne z filozofią v0.7.50);
restore przywraca każdą odczytaną wartość; gdy magazyn już właściwy — no-op.

### 9. ✅ Whitelist SQL w `/admin/query` bypassowalna

`Contains("DELETE ")` nie łapał `DELETE\tFROM` / `DELETE\nFROM` / `EXEC(`.
**Fix:** regex z granicami słów `\b(INSERT|UPDATE|...)\b` (IgnoreCase) na całym
SQL — tab/newline/nawias po słowie kluczowym już nie pomagają; identyfikatory
typu `created_at` nie są łapane (`_` to znak słowa). Nadal defense-in-depth —
docelowo dedykowany user SQL read-only (otwarte).

## Drobne (otwarte)

- ⬜ Komentarz przy `gt.Uruchom(0, 4)` błędny — wg docs 0 = `gtaUruchomDopasuj`,
  4 = `gtaUruchomWTle` (wartości OK, opis nie).
- ⬜ Kolekcje z `OtworzKolekcje` nigdy nie zwalniane (powolny wyciek RCW na STA).
- ⬜ `ct.Register` w `RunOnStaAsync` bez dispose rejestracji.
- ⬜ Ilości są `int` (`Quantity`, `IloscJmPoKorekcie`) — towary z ułamkami (kg/m)
  nie przejdą.
- ⬜ Filtr `nip` w GET /invoices używa kolumny `dok_NabKodSlownik` —
  do weryfikacji na bazie klienta (CHM nie opisuje schematu SQL).
- ⬜ Brak walidacji limitu 16 znaków `Symbol` kontrahenta (pułapka `0x80040E21`
  z CLAUDE.md) — zły symbol kończy się jako 500 zamiast czytelnego 422.
